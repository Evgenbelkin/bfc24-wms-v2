# Бриф: обёртка веб-приложения BFC24 WMS в Android-приложение (Capacitor)

Контекст для нового чата — чтобы не пересобирать всё заново. Ниже то, что уже
выяснено по текущему проекту и что важно знать перед началом работы.

## Зачем

Сотрудники сейчас работают через обычный браузер (адрес `dev.bfc-24.ru` /
`staging.bfc-24.ru`, добавленный на главный экран). Хотим — полноценное
Android-приложение: иконка, без адресной строки браузера, более надёжный
доступ к камере для сканирования.

## Что уже выяснили по технической части — важно не переделывать заново

1. **Фронтенд — простые статические HTML-страницы**, без сборщика (не
   Webpack/Vite/React). Страницы лежат в `public/app/*.html`, общий JS — в
   `public/shared/` (`api.js`, `ui.js`, `scanner.js`). Каждая HTML-страница
   самодостаточна, со встроенными `<script>`/`<style>`.

2. **`public/shared/api.js` использует ОТНОСИТЕЛЬНЫЙ путь** для всех запросов:
   ```js
   const API_BASE = '/api/v2';
   ```
   Это значит: самый простой и низкорисковый способ обернуть приложение —
   режим Capacitor **"remote URL"** (в `capacitor.config.ts` указать
   `server: { url: 'https://dev.bfc-24.ru' }`), при котором нативная оболочка
   просто открывает WebView на реальный домен — ТОЧНО как в обычном браузере.
   Это НЕ требует переписывать `API_BASE` на абсолютный адрес и не требует
   правки CORS — всё остаётся same-origin, как сейчас.

   Альтернатива (сборка `public/` в локальные ассеты приложения, стандартный
   для Capacitor подход через папку `www/`) потребовала бы: (а) сделать
   `API_BASE` абсолютным и переключаемым по окружению (прод/staging), и
   (б) добавить origin приложения (`capacitor://localhost` или
   `https://localhost`) в `CORS_ORIGINS` на сервере. Это лишняя работа без
   явной необходимости — начинать стоит с варианта "remote URL".

3. **Авторизация** — токены (`accessToken`/`refreshToken`/`user`) хранятся в
   `localStorage` (см. `getToken()`/`saveAuth()` в `api.js`). Работает без
   изменений в любом WebView, включая Capacitor.

4. **Сканирование через камеру** уже реализовано (`public/shared/scanner.js`,
   через `getUserMedia`) и работает в браузере уже сейчас. В Capacitor должно
   продолжить работать, но нужно будет запросить разрешение на камеру в
   `AndroidManifest.xml` и протестировать на реальном устройстве.

5. **Иконок/manifest.json для PWA пока нет** — под нативную оболочку это
   отдельные ассеты (иконки, splash screen), не пересекаются с веб-кодом,
   их нужно будет подготовить с нуля.

6. **CORS**: сейчас `CORS_ORIGINS` на VPS = `https://dev.bfc-24.ru` (боевой) /
   `https://staging.bfc-24.ru` (staging). Если пойдём по пути "remote URL" —
   менять не нужно. Если решим всё же бандлить статику локально в приложение —
   тогда придётся добавить origin приложения в этот список на обоих серверах.

## Важное ограничение — старый ТСД Honeywell ScanPal EDA50K

На складе используется терминал сбора данных Honeywell ScanPal EDA50K на
**Android 4.4.4 (KitKat, 2014 год)**. Никакое нативное/Capacitor-приложение
на нём не запустится — минимальные требования Capacitor и большинства
современных Android-инструментов начинаются от Android 6-7. Для этого
конкретного устройства решение отдельное и уже обсуждено в другом месте:
установка старого совместимого браузера (Firefox 68.11.0 — последняя версия
с поддержкой Android 4.4) через sideload APK, приложение остаётся веб-версией.
Задача Capacitor-обёртки касается **обычных телефонов сотрудников** (не
древних терминалов) — там ограничений по версии Android нет.

## Что нужно решить/сделать в новом чате

1. Выбрать окружение сборки: Capacitor CLI + Android Studio с Android SDK —
   этого нет в песочнице (headless Linux без Android SDK/эмулятора), сборку
   APK, скорее всего, придётся делать на твоём Windows-компьютере с
   установленным Android Studio, либо через облачный CI (например GitHub
   Actions с Android-раннером).
2. Определиться: приложение всегда указывает на боевой `dev.bfc-24.ru`, или
   нужен переключатель окружений (для тестирования на staging)?
3. Название приложения, app ID (например `ru.bfc24.wms`), иконка, splash.
4. Способ распространения: просто раздавать APK сотрудникам (sideload,
   как и с браузером сейчас) — Play Store не обязателен для внутреннего
   корпоративного инструмента.

## Структура репозитория (для ориентира)

```

public/app/*.html      — страницы приложения (одностраничники)
public/shared/         — общий JS (api.js, ui.js, scanner.js)
deploy/                — этот бриф + инструкция по staging
```
